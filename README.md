# 取件助手（PickTool）

取件快捷工具，支持 Android 和 iOS：把菜鸟、淘宝、拼多多的取件码 / 身份码，以及淘宝、拼多多、京东、小红书、美团、抖音的订单 / 待取列表，收进一个界面或一个快捷指令里。

点击即可直达对应 App 的内部页面；对应 App 未安装或无法直达时，自动改用网页入口。不读取短信、通知、相册或账号数据，没有后台服务，也没有广告。


## 功能

### 取件码直达

菜鸟身份码、淘宝取件码、拼多多身份码，点击后直接打开对应平台页面。

### 待取快递

淘宝、拼多多、京东、小红书、美团、抖音的订单 / 待取列表，一处查看不用来回翻 App。

### 多入口快捷方式

| 平台 | Android | iOS |
| --- | --- | --- |
| 取件码 | 主界面卡片、长按菜单、固定到桌面 | 快捷指令菜单 |
| 待取列表 | 主界面网格、长按菜单、桌面小组件 | 快捷指令菜单 |
| 网页兜底 | 自动降级到网页入口 | 快捷指令可配置 https 链接 |

### 网页兜底

当目标 App 未安装，或者 App 版本更新后内部页面无法直达时，会尝试打开对应的网页入口。所有入口地址集中在 `Destination.java`，便于逐个维护。

## iOS 使用说明

iOS 不需要安装 App，用一个快捷指令就能把全部入口放到桌面。

### 一键添加（推荐）

iPhone 或 iPad 上用 Safari 打开下面的链接，点「获取快捷指令」→「添加快捷指令」：

**<https://www.icloud.com/shortcuts/d8b71aec8f2b4fe7ae4c6af1880fe376>**

添加完成后，在「快捷指令」App 里点一下它测试，会弹出入口菜单，选对应的项目就能跳转（暂无抖音和美团，需要的自行添加）。

### 添加到主屏幕

1. 打开「快捷指令」App，找到刚添加的「取件助手」；
2. 点右上角「⋯」或长按它，选择「分享」；
3. 选择「添加到主屏幕」，命名后点「添加」；
4. 桌面出现图标，之后点它就弹出菜单。

### 使用方式

点桌面图标 → 弹出菜单 → 选择「菜鸟身份码 / 淘宝取件码 / 拼多多身份码 / 淘宝待取 / 拼多多待取 / 京东待取 / 小红书待取 / 美团订单 / 抖音商城」→ 自动跳转对应 App。


## Android 使用说明

### 安装

1. 下载 APK 并安装；
2. 打开应用，主界面即为入口合集。

### 使用方式

1. 点击顶部卡片打开取件码，或点击中部网格查看待取列表；
2. 需要更快入口时，长按应用图标使用快捷方式；
3. 点击底部胶囊按钮，把入口固定为独立桌面图标；
4. 还可以在主屏添加「取件助手」小组件，把五个入口放到桌面上。

### 长按快捷方式

长按桌面上的应用图标，可以直接进入 7 个入口：菜鸟身份码、淘宝取件码、拼多多身份码、淘宝待取快递、拼多多待取快递、京东待取快递、小红书待取快递。快捷方式由 `res/xml/shortcuts.xml` 静态声明。

### 固定到桌面

主界面底部的胶囊按钮可以把菜鸟、淘宝、拼多多三个入口固定为独立的桌面图标。固定后的图标点击直接进入对应页面，图标与长按菜单共用同一套资源（`ic_shortcut_*.xml`）。

需要注意：已经固定在桌面上的快捷方式是启动器缓存的位图，应用更新后不会自动刷新。如果图标资源有变化，需要删掉旧图标重新固定一次。

### 桌面小组件

提供 5 个按钮的一行小组件：菜鸟、淘宝、拼多多、京东、小红书。小组件可水平、垂直缩放，点击按钮直接打开对应入口，不需要先打开应用。

## 界面

Android 主界面采用 Material 3 风格的暖色配色，自上而下依次是：


页面支持滚动，底部署名栏固定在屏幕底部，不随内容滚动。状态栏、导航栏与刘海区域做了安全区适配。

### 主要模块

| 文件 | 职责 |
| --- | --- |
| `MainActivity.java` | 主界面布局与交互，底部署名栏 |
| `Destination.java` | 各平台的深链、包名与网页地址 |
| `DeepLinkLauncher.java` | 依次尝试 App 深链、官方 App、网页入口 |
| `ShortcutPinning.java` | 把入口固定为桌面快捷方式 |
| `PickupWidgetProvider.java` | 桌面小组件的按钮与跳转 |
| `M3.java` | Material 3 配色与卡片样式 |
| `ic_shortcut_*.xml` | 长按菜单与固定图标共用的图标资源 |

## 构建

环境要求：JDK 17 和 Android SDK 35。应用最低支持 Android 6.0（API 23），编译与目标版本为 SDK 35。

```powershell
.\gradlew.bat assembleDebug
```

调试 APK 输出到：

```text
app/build/outputs/apk/debug/app-debug.apk
```

安装到已连接的设备：

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## 发布版签名

仓库不包含任何签名相关文件。需要发布版时，构建方自行准备签名材料并放在工程根目录，然后执行：

```powershell
.\gradlew.bat assembleRelease
```

签名材料与口令请自行保管，不要提交到公开仓库。更新应用时需继续使用同一套签名，否则无法覆盖安装。

## 深链维护

应用和快捷指令使用的都是第三方 App 的内部页面入口，这些入口并非稳定的开放 API，对应 App 更新后可能失效。发布前应在真机上逐个测试；Android 侧失效时更新 `Destination.java` 中的地址即可，iOS 侧更新快捷指令里的 URL。

Android 各入口的兜底顺序是：

1. 依次尝试该平台的 App 深链；
2. 深链不可用时，视情况尝试直接打开官方 App；
3. 仍然失败时，打开对应的网页入口。

## 设计说明

- **数据最小化**：不读取短信、通知、相册或任何账号数据。
- **Android 不申请网络权限**：应用自身不联网，网页兜底交给系统浏览器处理。
- **不做后台常驻**：没有服务、没有轮询、没有广告 SDK。
- **图标统一**：长按菜单与固定到桌面的图标共用同一套品牌色资源，减少重复维护。
- **无第三方依赖**：只用 Android 系统 API 与 Gradle 构建，APK 体积小。
